# 12. Tabs

Date: 2026-10-10

## Status

Accepted

## Context

The app is meant to grow beyond the inbox, and some of that growth belongs to one company alone: a tab showing what Productive's internal systems know about the customer in the open conversation means nothing to anyone else. Such a tab should live in that company's own private repository, not in a fork: a fork of a public GitHub repository is always public, and a private copy has to merge every upstream change by hand.

Go programs take extensions in a few ways, and only one lets an extension draw a whole screen of its own inside a Bubble Tea app:

- **Commands bound to keys** (k9s, lazygit, gh-dash) run a shell command and show its output or hand it the terminal.
- **Separate processes** speaking gRPC through `hashicorp/go-plugin` (Terraform, Vault), JSON over stdio (marchat) or MCP (crush) return data for the host to render.
- **Embedded interpreters and WASM** (micro's Lua, Traefik's Yaegi, Extism) expose what the host chooses, with no precedent for drawing a Bubble Tea view.
- **Compiled-in modules** (Caddy built with `xcaddy`, CoreDNS) are Go packages that a small custom build links in. An extension is then a full `tea.Model`, type-checked against the host.

No surveyed Go application ships a runtime plugin that draws its own tab.

Go's rules shape the packages. Code under an internal directory is importable only from this module, so the contract a company's tab implements has to sit outside it. The package that starts the app builds the inbox, and the inbox implements the contract, so the contract and the starter cannot share a package without an import cycle. Go's module layout guide puts a repository's importable package at its root and its commands under a cmd directory. The name `app` meets Go's package naming rules: short, lower case, and none of the meaningless names the Go blog warns against.

## Decision

- **The app is a frame holding tabs.** The frame is the only top-level Bubble Tea model. It draws the tab bar, owns the global keys (switching tabs, quitting, help), the window size and the theme, and passes everything else on: a key press to the active tab only, every other message to every tab, so a poll the inbox started still lands while another tab is in front.
- **Global keys are never plain letters**, so text typed into a tab, such as the inbox's composer, never reaches them.
- **v1 has one tab, the inbox**, built as ADR 0008 describes. With a single tab the tab bar is hidden, so v1 shows only the inbox.
- **The contract a tab implements is the public package `app`**, and holds only:
  - the `Tab` interface: a title, `Init`, `Update` returning the updated tab, and `View` given the width and height the frame allots it;
  - a message sent to every tab whenever the open conversation changes, carrying its contact's Intercom id, name and email, or no contact when none is open;
  - the palette of ADR 0009's twenty roles, sent to every tab in a message at start and again whenever the light or dark flavour changes.
- **The root package `intercomifico` starts the app** with `Run(extra ...app.Tab) error`: it reads the settings and token per ADR 0004, builds the Intercom client, the frame and the inbox, and adds the extra tabs after it.
- **The `main` package moves to `cmd/intercomifico`** and calls `Run` with no extra tabs.
- **A company's own build** is a repository of its own whose `main` calls `intercomifico.Run` with its tabs, and which updates to a new release of this one with `go get`.

## Consequences

- A company keeps its tab private and takes this repository's changes by version, never by merge.
- The `app` package is a promise to every outside build. While releases are `v0.x` it may change; from `v1.0.0` a breaking change means a new major version and a new import path.
- An outside tab gets no Intercom client and no settings: what it knows of Intercom is the open contact. Widening that is a new ADR.
- ADR 0007's rule on disk writes binds this repository's code; what an outside tab stores is its builder's responsibility.
- The app is installed with `go install github.com/izkreny/intercomifico/cmd/intercomifico@latest`.
- Plugins loaded at run time, without a custom build, remain a later ADR.
